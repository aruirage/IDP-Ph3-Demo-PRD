# PRD 板块计划

## 交付范围

在现有产品四个入口制作桌面增量原型，保留原菜单和主要布局。六项需求独立呈现：主数据更新、层级与回溯、OCR 确认、容量、二维码、全局模型。本文为 G1 待审核过程文件，不代表原型已完成。

## 制作顺序

1. 完成产品定义、用户需求与用户旅程基础文档；不重复扩写无增量的旧产品功能。
2. 依据 manual 截图确认共享视觉，完成表格、弹窗、候选、反馈与异常状态参考页。
3. 主数据设定：保留左侧 Master 列表和右侧表格，制作列设置、阈值、层级查看、手动导入、归属核对及每日更新结果。十万行超限作为该菜单的状态，不新增容量菜单。
4. 我的任务→OCR 抽出确认：原文与当前字段值同时展示，自动替换、候选选择、人工修正；不提供重新照合。
5. 账票类别设定第 2～3 步：第 2 步移除模型选择，保留账票告警规则；第 3 步扩展 QR 全文／分隔取值。字段引用与同组检索沿用现有方式。
6. 模型设定：用途指派的 OCR 卡片统一主模型和验证模型；全局应用，其他用途沿用。
7. 全局检查页面导航、标注、左右对照、规则图、状态演示与导出。

## 模块与页面规划

| 模块 ID | 目标与边界 | 依赖 | 原型页规划 | 审核标准 |
| --- | --- | --- | --- | --- |
| product-definition | 产品定位、六项增量及非目标 | G0 基线 | 无 | 不扩写旧产品模块 |
| users-and-needs | 管理员、经办人需求 | 用户确认与 manual | 无 | 需求与角色可追溯 |
| stories-and-journey | 导入、更新、照合、人工修正旅程 | 主数据结构 | 无 | 分支、失败出口和最终值清楚 |
| master-sync | 每日全量取数、差异更新、手动导入及异常隔离 | 主数据、归属、向量状态 | master-data, master-import, master-review, master-update | 获取不完整不生效，零条当次授权，异常版本隔离 |
| master-hierarchy | ICD 内置归属及其他树形数据，OCR 匹配判定 | 官方 2013、客户记录 | master-hierarchy, match-rules | 导入无类似度，OCR 三层判定和阈值优先，不造父级 |
| ocr-confirm | 已有 OCR 确认页增量 | 已保存照合快照 | ocr-confirm | 自动替换、原文可见、人工值优先、无重新照合 |
| master-capacity | 十万条客户记录上限 | 导入／更新入口 | 复用主数据状态页 | 官方节点不计数，超限整批失败 |
| qr-config | 第 3 步 QR 规则增量 | 第 2 步提示词与正解 | doctype-step-2, doctype-step-3 | 全文兼容，分隔取段，多源歧义 OCR，不切分 OCR 结果 |
| model-config | 全局 OCR 模型配置 | 既有模型资源 | model-settings | 单一配置来源，所有账票新调用生效 |

页面名称为规划，实际实现时逐页登记 manifest，不预建不存在的页面引用。状态演示按模块提供；模拟接口、模型和匹配候选有演示标识。

## 原型关系

主数据列表→配置／导入→归属核对→更新结果→主数据列表。
主数据列表→层级查看；匹配规则演示→OCR 确认场景。
账票第 2 步→第 3 步；模型设定与账票读取配置只读摘要对应，不新增账票级模型覆盖。

所有原生页面跳转与 manifest 关系保持一致。先维护关系，再用底座自动排列画布。

## 视觉与状态

按用户指定 manual 截图：既有侧栏、蓝白表格、浅灰背景、紧凑控件、现有弹窗风格，1440×900 桌面视口。产品日语文案，PRD 和标注中文。

覆盖：正常、加载、空、异常、待管理员确认、更新排队、零条清空授权、超限失败、自动采用、人工修正、QR 来源歧义。

## 审核方式

本计划通过后进入基础文档；视觉基线和每个功能模块按技能逐项交付审核。每个功能包包含对应 PRD、可点击原型、状态页、定位标注和关系检查。
